## 開發記錄

原 `epic-11-txt-engine`（TXT 直排引擎，自訂輕量排版引擎路線），2026-08-16 `/grill-with-docs` 依外部研究報告（`docs/research/comprehensive_format_expansion_research.md`）評估後改弦更張並擴大範圍：TXT 技術路線推翻原案，改與 Markdown (MD) 共用既有 `readest/foliate-js` 渲染管線（不再自建排版引擎），並一併擴充支援 KF8 (AZW3)、CBZ 兩種新格式；MOBI／FB2 經評估後排除於本次範圍，列為未來獨立評估項目。核心架構決策（`FoliateEpubReaderView` 泛化為 `FoliateReaderView`、`Book.isFixedLayout` 欄位廣義化涵蓋 CBZ、TXT/MD 匯入時落地轉換為合成 EPUB 結構、純 Dart-only 格式解析、KF8 DRM 偵測等）記錄於 ADR 0023；PRD 同步修訂新增 FR-43（P1）並擴充 FR-05/06/07/27/41 之格式清單，詳見 `docs/prd.md` 2026-08-16 editHistory。2026-08-16 完成 Discovery（`design.md`）：比照 `epic-17`/`epic-20` 先例，Issue 1 定為前置驗證 Spike（KF8／CBZ vendor 資產整合可行性），GO 後才展開完整 Architecting/Scrum Master 拆解。2026-08-16 **Issue 1 Spike 已完成，結論 GO**（真機驗證 KF8/CBZ 開書可行、DRM 位元組偵測可行，完整證據見 `reviews/spike-issue1-kf8-cbz-drm.md`）；執行審查（`reviews/review-issue-1-spike-execution.md`）核實證據鏈真實可信，核准通過並採納 2 項 Important／1 項 Minor 修正（CBZ RTL 待落實事項補充「導覽方向尚未驗證」的精確措辭、KF8 測試素材替代說明），已回填至 `issues.md`；2026-08-16 完成 Architecting（`spec.md`）：綜合 `design.md`／ADR 0023／Issue 1 Spike 驗證結果撰寫，含 KF8 DRM 偵測、CBZ 自然排序/RTL 覆蓋、TXT/MD 合成書籍結構與內容指紋計算順序、`isFixedLayout`/`epubLocator` 欄位語意廣義化等核心介面決策；測試 seam 定案為「匯入/解析管線（`flutter test`）＋ `FoliateReaderView`/`ReaderScreen`（`integration_test`）」兩層。2026-08-16 完成 Scrum Master 階段：`issues.md` 拆出 Issue 2-5 共 4 個垂直切片工單（Issue 2 KF8 匯入與閱讀／Issue 3 CBZ 匯入與閱讀含 RTL Dart `kf8_metadata.dart`（PDB/MOBI/EXTH 解析、DRM 位元組偵測）、匯入管線接線；程式碼審查（`reviews/review-issue-2.md`／`reviews/review-issue-2-verification.md`）發現 2 項 Critical（`content://` URI 未實作導致標準匯入流程下 AZW3 完全無法開啟）與 2 項 Important，已全數修復並補上 7 筆迴歸測試，`flutter test` 全專案 1312 tests 全過、真機整合測試 2/2 通過。**2026-08-16 Issue 3（CBZ 匯入與閱讀，含翻頁方向切換 RTL/LTR）已完成並合併回 `main`**（PR 通過。**2026-08-17 Issue 4（TXT 合成書籍結構與閱讀）已完成並合併回 `main`**（PR [#154](https://git.jigong.org/huthief/elinkBook/pulls/154)，分支 `epic-11/issue-4-txt`，commit `23f1b58`）：`BookFormat`/`BookFileFormat` 新增 已修復的快取副檔名感知機制、零額外原生/JS 改動；`contentFingerprint` 對原始檔案計算，合成檔案刪除清理由既有通用邏輯自動涵蓋。程式碼審查（`reviews/review-issue-4-plan.md`／`reviews/review-issue-4.md`）發現 2 項 Important——**#1**：Task 8 一度遺漏 `isComicBookHint` 參數，導致 CBZ 的 RTL 覆寫在分支中間提交區間內被靜默跳過，未被 `flutter test` 攔截；**#2**：CBZ RTL 端到端驗證強度在同一次「docs」提交中被弱化且未說明原因。修復過程中，恢復驗證強度後真機實測意外戳破一個**從 Issue 1 Spike 沿用到 Issue 3、從未真機驗證過的錯誤假設**——「RTL 模式下熱區『上一頁』動作應讓頁碼前進」；追查 `fixed-layout.js` 原始碼並交叉比對本專案已出貨的 PDF `dualPageDirection` 實作，確認 CBZ 預設單頁模式下 `book.dir` 對熱區導覽方向本無作用（僅雙頁跨頁視覺排版才生效），這是本 App 一致的既定設計哲學，非缺陷。經人類確認決策：**翻頁的規則以熱區為準**——`spec.md`「CBZ 支援」與 `issues.md` Issue 3 條目已同步修正相關措辭（原文保留，附加架構修正說明）。修復後 `flutter test` 全專案 1383 tests 全過、真機整合測試（CBZ 3/3、TXT 3/3）皆通過。**2026-08-17 Issue 5（MD 合成書籍結構與閱讀）已完成並合併回 `main`**（PR 4，`txt_epub_synthesizer.dart` 改用）。程式碼審查（`reviews/review-issue-5.md`）發現 1 項 Critical——`package:markdown` 對使用者輸入中的裸 HTML（raw HTML passthrough，如手打 `<br>`）不會跳脫，導致合成章節 XHTML 可能不是合法 XML，而 `epub.js` 以嚴格 XML
