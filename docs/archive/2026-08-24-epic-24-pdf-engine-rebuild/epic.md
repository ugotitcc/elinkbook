## 開發記錄

2026-08-06 使用者依 `tmp/pdf_reader_solutions_research.md` 研究報告提出：現行 PDF 架構（`android.graphics.pdf.PdfRenderer`）無法滿足雙頁並列/TOC 目錄/搜尋/縮圖/畫線註記 5 大需求，建議改用 `pdfrx`（PDFium + Dart FFI）；`/grill-with-docs` 查證 ADR 0001 當初排除 PDFium 的伏筆條款（「若平台 API 無法滿足 FR-11 影像濾鏡/裁切需求，可再重新檢視」）並未真正觸發——FR-11 已用原生架構在 `epic-4-pdf-enhance` 成功上線，本次觸發理由是全新需求（TOC 等），非原條款情境，決策記於新增的 **ADR 0022**（`docs/adr/0022-pdf-engine-migrate-to-pdfrx.md`，同步更新 ADR 0001 狀態註記）。逐項確認範圍：(1) **完全替換**引擎，非漸進共存，現行 `PdfReaderView.kt`／`PdfReaderView` 整套退場；(2) **E-Ink 影像濾鏡/裁切（FR-11）功能對等列為必要驗收條件**，不接受功能退化（研究報告本身承認此為缺口、未給具體方案）；(3) 使用者引用 saber-notes/saber 提出的「手寫筆記/PDF 標註」經確認是指真正的自由繪圖（stylus 壓力感測），與既有文字選取劃線系統是不同互動模式，**明確排除本 Epic**、另立後續獨立 Epic；(4)
