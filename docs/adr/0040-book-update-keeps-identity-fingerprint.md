# ADR 0040：書籍更新版取代時，書籍 ID 與內容指紋維持舊值，同步身份與檔案內容脫鉤

## 狀態

已採納（2026-11-03 `/grill-with-docs`，書籍更新版判定）

## 背景

出版社可能釋出同一本書的修訂檔。現況本機匯入只比對來源 URI（`filePath`），更新檔會被當成全新的一本書，舊書的閱讀進度、書籤、劃線與備註留在舊書上；雲端／遠端下載的 EPUB 則可能因 OPF identifier 相同而被判為「已存在」直接跳過，更新檔進不來。

跨裝置同步以 `books.content_fingerprint` 對應「同一本書」（見 `CONTEXT.md`「書籍內容指紋」）。PDF／TXT／CBZ 的指紋是整檔 SHA-256，檔案內容一變指紋就變。因此「取代檔案」會直接牽動同步身份，必須先決定指紋怎麼處理。

## 決策

使用者選擇「取代」更新版時：

1. **`Book.id` 與 `content_fingerprint` 維持舊值，不重算。** 書籍的跨裝置身份跟檔案內容脫鉤，註記與閱讀位置可繼續依舊指紋同步，不需異動 PocketBase 端資料。
2. 更新版的判定與處置規則（兩層身份判定、取代／並存／跳過、批次彙整清單、失敗時先處理新檔再換檔）以 `CONTEXT.md`「書籍更新版」為準，不在此重複。

## 被否決的方案

- **指紋改成新檔的值**：其他裝置會把新指紋視為另一本書，舊指紋下的劃線、書籤與閱讀位置成為孤兒。
- **雙指紋欄位**（`identity_fingerprint` 與 `file_fingerprint` 分開存）：模型較乾淨，但需要 migration 與同步欄位異動。**延後而非否決**——若實務發現下方代價不可接受，再升級為此方案。

## 後果與已知代價

- 於另一台裝置單純匯入同一份新檔，PDF 等整檔雜湊格式會算出新指紋而成為另一本書，除非該裝置也對舊書執行一次「取代」流程。EPUB 以 identifier 為指紋，不受影響。
- 資料庫中的指紋不再等於現存檔案的實際雜湊。任何「指紋＝檔案雜湊」的假設（例如 `relinkBook` 的內容比對）對曾被取代的書都不再成立，改動相關程式前須知悉。因此 `relinkBook` 在內容不符、格式相同時，改為詢問使用者「強制重新連結」（對所有書通用，不另記錄哪本書被取代過）。
- 註記失效不持久化，因為新增狀態欄位會牽動 PocketBase 同步，違背本決策免動同步端的前提。改為跳轉時降級處理（見 `epic-67` 的 `epic.md`）。
- 取代後舊檔不保留、不提供復原。
