# ADR 0045：Foliate 每個章節從新的一頁（跨頁）開始（重新開放 ADR 0011 的「不修改釘定版本」）

## 狀態

已採納

## 背景

重新開書時必須回到使用者離開的「同一頁」。實測發現直排（以及橫排雙欄）時，同一個 CFI「連續翻頁看到的分頁」與「重新開書看到的分頁」相差半頁（一欄）：

- `paginator.js` 的 `View.expand()` 以「欄」為單位計算章節大小，註解明講這是刻意的——讓相鄰章節在章節不足整頁時共用同一個跨頁（spread）。
- 因此一個章節從第幾欄開始，取決於前面章節佔了奇數還是偶數欄。直排一頁是 2 欄（頁高 752px、欄高 376px），前一章若佔 49 欄（24.5 頁），下一章的第一欄就落在上一個跨頁的後半，之後所有分頁都偏半頁。
- 重新開書時沒有載入前面的章節，章節從第 0 欄起算，分頁邊界與離開時不同。儲存的 CFI 範圍起點落在「後半欄」時，會被歸到較早的那一頁，使用者看到的是離開位置的前一頁。

橫排單欄（手機）不受影響，因為一頁就是一欄。

## 決策

- 在 `paginator.js` 的 `View.expand()` 加一個**本地補丁**：章節版面尺寸補滿整個跨頁（`Math.ceil(欄數 / 每頁欄數) * 每頁欄數 * 欄高`），讓每個章節都從新的一頁開始。分頁邊界只取決於章節本身，與進入路徑無關。
- `#contentPages` 維持真實欄數，不受補齊影響（進度比例、`needsPrev` 判斷沿用上游語意）。
- 單欄佈局（`columnCount = 1`）補齊後與上游完全相同，不改變行為。
- 補丁以 `elink 本地補丁（ADR 0045）` 註解標記。**升級釘定的 readest/foliate-js 版本後必須重新套用**（若整份覆蓋 `paginator.js` 會被移除），並重跑 `app/tool/foliate_touch_harness/scenario-resume-mid-chapter.mjs` 確認。

## 後果

- 章節標題永遠出現在該章第一頁的頁首，不會與上一章的最後一欄共用同一頁；短章節（例如封面、獻詞）會獨佔一個跨頁。這與一般閱讀器的預期一致。
- 章節結尾若只佔跨頁的前半，後半留白。
- 重新開書回到與離開時完全相同的頁，不再依賴進入路徑。
- `paginator.js` 不再與上游逐位元組相同，同步上游時需手動重套這個補丁（與 ADR 0024 同類的維護成本）。

## 曾考慮的替代方案

- **重新開書時一併載入前面所有章節，重現相同的欄位奇偶**：奇偶取決於整本書前面所有章節的欄數總和，且 Foliate 會卸載遠處章節後重新換算位移，路徑相依的行為難以重現，予以排除。
- **在 `main.js` 以 MutationObserver 改寫章節 view 的 `style` 補齊尺寸**：與 `expand()` 的 ResizeObserver／`onExpand` 捲動邊界計算競爭，時序脆弱，予以排除。
- **在章節內容尾端插入 `break-before: column` 的空白元素補欄**：會讓 CFI 可能指到不屬於書本的元素，並影響 TTS、搜尋索引與簡繁轉換的文字走訪，予以排除。
- **還原時把捲動位置微調半頁**：Paginator 的翻頁、貼齊與邊界都以整頁為單位，半頁位移會破壞後續翻頁，予以排除。
