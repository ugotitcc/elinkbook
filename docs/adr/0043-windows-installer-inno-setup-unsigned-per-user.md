# ADR 0043：Windows 發佈形式採 Inno Setup 安裝程式（不簽章、依使用者安裝、固定 AppId），並保留 zip 免安裝版

## 狀態

已採納（2026-11-13）。對應 `epic-66-windows-port` Issue 27。承接 Issue 14（免安裝 zip）與 epic-66 決策 10（「先自用」）；Windows 版改為對外發佈後，決策 10 的「先自用」不再適用。

## 背景

Windows 版原本只有免安裝 zip（Issue 14）。對外發佈需要一般使用者習慣的安裝程式：有開始功能表項目、可從「設定 → 應用程式」解除安裝、可直接覆蓋升級。作者沒有程式碼簽章憑證；原本沒有第二台機器可驗證，後來使用者在另一台電腦裝過一次（回報原文，環境未查證）。App 資料與程式資料夾分開，且**分放在兩處**：`%APPDATA%\cc.ugotit\elinkbook`（WebView2 資料、已下載字型、字典來源），以及使用者的「文件」資料夾（`library.db`、`covers`、`imported_books`，即書庫與匯入的書）。

## 決策

1. **安裝程式用 Inno Setup**，輸出單一 `elinkbook-<版本>-windows-x64-setup.exe`；zip 免安裝版保留，兩者並列於 Release。
2. **不簽章**。安裝程式與 zip 一樣會跳 SmartScreen「仍要執行」，沿用 `app/windows/packaging/README.txt` 的說明。有使用者回報被擋時，再另開 Issue 評估憑證。
3. **依目前使用者安裝**：預設 `%LOCALAPPDATA%\Programs\elinkBook`，不需系統管理員權限。
4. **固定 `AppId`（GUID）**：新版直接覆蓋安裝舊版，安裝時 App 正在執行會被關閉。**這個 GUID 一經發佈就不可更改**——改了之後，Windows 會把新舊版視為兩個不同的 App，舊版使用者無法覆蓋升級，只會並存兩份。
5. **解除安裝預設保留使用者資料**，但跳出詢問「是否同時刪除 elinkBook 的所有資料（包含書庫）」，預設「否」；選「是」刪除兩個資料夾：`%APPDATA%\cc.ugotit\elinkbook`，以及「文件」資料夾下的 `elinkbook`（見 [ADR 0044](0044-windows-data-under-documents-elinkbook.md)）；靜默解除安裝（`/SILENT`、`/VERYSILENT`）一律不詢問、不刪。（歷程：原本只刪 `%APPDATA%` 卻寫成「刪書庫」；2026-11-13 獨立審查發現後，使用者決定連書庫一併刪除，先以「文件」根目錄的固定名稱清單實作；同日 Issue 29 把資料收進 `文件\elinkbook`，改為只刪這兩個資料夾，不再有通用名稱清單。）
6. **App 執行中拒絕解除安裝**：解除安裝程式不會像安裝程式那樣關閉執行中的 App，檔案被鎖住刪不掉卻會移除登錄項，所以以視窗類別加標題偵測，執行中就中止。

## 替代方案與取捨

- **MSIX**：被否決。沒有受信任的憑證簽章就無法雙擊安裝，等於一定要先取得憑證；Windows 10 1809 與 MSIX 的相容條件也增加變數。
- **只維持 zip**：被否決。沒有「設定 → 應用程式」的移除入口，也沒有開始功能表與一般使用者預期的升級方式。
- **依機器安裝（`Program Files`）**：被否決。需要系統管理員權限，且與 zip 版「不需要管理員」的體驗不一致。
- **解除安裝一律刪除或一律保留、不詢問**：被否決。一律刪除會誤刪使用者的資料；一律保留則使用者沒有直接清乾淨的途徑。

## 後果

- 未簽章意味著 SmartScreen 警示不會因為安裝程式而消失，這是已知且接受的代價。
- zip 版與安裝版可並存，兩者共用同一份資料，**不可同時開兩份**，說明文件須提醒。
- **解除安裝刪除範圍是兩個明確屬於本 App 的資料夾**（Issue 29 之後）：不再對「文件」根目錄的通用名稱（`covers`、`imported_books` 等）逐項刪除，沒有誤刪使用者同名資料夾的風險，也沒有名單需與 App 同步的維護成本。代價：Issue 29 之前的版本留在「文件」根目錄的舊項目不會被清掉，需手動刪除。
- 乾淨機器、Windows 10 1809 與 SmartScreen 實際行為仍未驗證；另一台電腦只有使用者回報的結果，沒有查證其環境。
