# ADR 0033：介面語言偏好採裝置本地儲存，不跨裝置同步

## 狀態

已採納

## 背景

`epic-45-interface-i18n`（FR-49 多語系介面）`/grill-with-docs` Discovery 階段需要決定「介面語言」（正體中文／簡體中文／英文）偏好設定要不要跟隨「elinkBook 同步帳號」（`epic-8-sync`）跨裝置同步。既有「全域預設值」（螢幕方向、翻頁模式、音量鍵翻頁等）一律儲存於裝置本地 `SharedPreferences`，不參與同步；但同步機制本身已存在且技術上可行，「要不要把語言也納入」並非顯而易見的選擇。

## 決策

介面語言偏好比照既有「全域預設值」慣例，儲存於裝置本地 `SharedPreferences`，**不**納入 `SyncEngine`／PocketBase 同步範圍。

理由：介面語言通常跟「這台裝置/使用情境」綁定，而非跟「這個人」綁定——例如同一帳號在公司電腦想用英文介面、家用平板想用中文介面是合理情境；強制跨裝置同步反而會在這類情境下造成使用者困擾。

## 後果

- 使用者在每台新裝置上須各自設定一次介面語言（比照現有全域預設值的既有體驗，非新增的不一致）。
- 若日後產品需求變成「使用者期待介面語言跟人走」，需要另外評估是否新增 PocketBase collection／欄位承載此偏好，屬於未來可逆的擴充，不影響本決策的既有實作。

## 曾考慮的替代方案

- **納入既有 Checkpoint 同步批次機制，新增一個 `user_prefs` collection**：技術上可行，但目前沒有任何「跨裝置一致」的產品需求佐證，屬於投機性工程；且需要新增 collection／schema，成本高於裝置本地儲存，予以排除。
