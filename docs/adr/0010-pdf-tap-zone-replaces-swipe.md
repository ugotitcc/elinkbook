# ADR 0010：PDF 移除橫向滑動翻頁手勢，改為純點擊熱區導覽

## 狀態

已採納（`epic-7-interaction` Discovery，`docs/epics/epic-7-interaction/design.md`）。

## 背景

`PdfReaderView.dart` 目前唯一的翻頁手勢是 `GestureDetector.onHorizontalDragEnd`（橫向拖曳滑動）。`epic-6-annotations` Issue 3 又在同一個 `GestureDetector` 上疊加了長按拖曳框選（劃線），兩者共用同一個手勢競技場（gesture arena），`docs/adr/0008-pdf-annotation-long-press-gesture.md` 已明文記錄「長按選取與既有手勢的優先權尚未實測」為未收斂風險。

`epic-7-interaction`（FR-24）要為 PDF 新增 3×3 點擊熱區導覽。若滑動翻頁與新的點擊熱區同時保留，同一個 `GestureDetector` 內將同時存在滑動翻頁、點擊熱區、長按拖曳框選三種手勢，彼此的優先權/誤觸風險疊加，需要更大量的真機驗證才能確認三者不會互相搶奪或誤觸發。

## 決策

新增 3×3 點擊熱區的同時，移除既有的橫向滑動翻頁手勢。PDF 的翻頁方式收斂為「點擊熱區」單一路徑（另有音量鍵 FR-18 與頁尾跳頁輸入框兩種既有輔助路徑，不受影響）。

## 後果

- 既有使用者原本熟悉的「左右滑動翻頁」手勢從 PDF 閱讀畫面移除，是有感的行為變更，需要在使用者可見處說明或引導（例如熱區輔助線開關）。
- 手勢競技場內只剩點擊熱區（`onTap`）與長按拖曳框選（`onLongPress*`）兩種手勢，Flutter 依「按住時長＋移動距離」即可自然區分兩者，複雜度低於三種手勢並存。
- 若日後有使用者強烈要求恢復滑動翻頁，需重新評估與點擊熱區、長按框選的三方共存方案，並比照 ADR 0008 的作法先在真機驗證手勢優先權。

## 曾考慮的替代方案

- **滑動與點擊熱區並存**：技術上 Flutter 的手勢競技場可以依移動距離/時長分辨 `onTap` 與 `onHorizontalDragEnd`，並非做不到。但保留兩種語意重疊的翻頁手勢（滑動＝翻頁、熱區點擊＝翻頁）會讓使用者對「點擊熱區到底會不會被滑動吃掉」感到不確定，且需要額外的真機測試涵蓋兩者交互，決定不保留以降低範圍與風險。
