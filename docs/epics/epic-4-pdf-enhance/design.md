# Epic 4 — PDF 專業增強：設計 (Design)

## 問題陳述

FR-11 要求 PDF 閱讀器支援三項專業增強功能：

1. **影像濾鏡**：對比度、亮度、加粗（改善掃描件/淡色文件的可讀性）。
2. **裁切**：智慧自動裁切（去除白邊/黑邊）與手動選區裁切。
3. **Page-fit 自適應顯示**：目前 FR-11 只寫「預設採用 Page-fit」，本次 Discovery 確認需求其實是要新增可切換的多種 fit 模式，Page-fit 只是其中的預設值。

目前 `PdfReaderView`（`app/android/app/src/main/kotlin/cc/ugotit/elinkbook/PdfReaderView.kt`）是純粹的 `ImageView` 點陣圖渲染，`ImageView` 未明確設定 `scaleType`（沿用 Android 預設 `FIT_CENTER`，已巧合符合 Page-fit 語意）；PDF 完全沒有任何版面設定 UI 入口——`reader_screen.dart:222` 的齒輪按鈕與 `ReaderSettingsSheet` 目前只在 `format == BookFormat.epub` 時顯示。本 epic 需要從零建立 PDF 專屬的設定入口與三項功能。

## 範圍界定（與相鄰 Epic 的邊界）

- **`epic-16-dual-page`（FR-41，橫向雙頁並排）**：已在先前的 `/grill-with-docs` 分流中獨立出去，排在本 epic 之後啟動，本 epic 不處理。
- **`epic-3-fonts-layout`**：Issue 10 已解決 EPUB 固定版面（漫畫）逐頁縮放不一致問題，其中「全書統一比例、取樣後固定」的手法是本 epic 智慧自動裁切粒度決策的直接參考先例。
- **`epic-14-system-settings`**：本 epic 討論後決議 PDF 的濾鏡/裁切/Fit 模式**皆不**採用 epic-3 那種「全域預設 + 單書覆寫」雙層模式，全部只做單書持久化，因此不需要併入 epic-14，維持 epic-4 內部自足。

## 決策紀錄（Discovery 逐項確認）

以下每項皆為 `/grilling` 逐一確認的產品決策，附推薦選項與實際採用結果：

| # | 決策點 | 採用結果 |
|---|---|---|
| 1 | 「加粗」的具體效果定義 | 筆畫增粗（型態學膨脹/dilate 處理），非文字 font-weight（PDF 是點陣圖，無文字節點可套用） |
| 2 | 影像濾鏡設定儲存層級 | 單書持久化（`book_reader_prefs`），無全域預設；理由：對比度/亮度是針對特定掃描件品質的調整，書與書之間通常無共通性，不像螢幕方向/翻頁模式那樣有跨書一致性需求 |
| 3 | 智慧自動裁切的計算粒度 | 全書統一比例（取樣後固定一次），非逐頁各自計算；直接沿用 epic-3 Issue 10 的教訓（逐頁獨立計算在數值些微不一致時會造成翻頁縮放跳動） |
| 4 | 手動選區裁切的適用範圍 | 套用到全書所有頁（與自動裁切行為一致），非僅套用於框選當下那一頁 |
| 5 | 自動裁切與手動裁切的關係 | 三選一互斥模式（不裁切／智慧自動／手動選區），非「手動微調自動結果」的疊加模式 |
| 6 | FR-11「預設 Page-fit」是否暗示需要其他可切換模式 | 是，需新增多種 fit 模式供切換（不只是確認/明確化現有行為） |
| 7 | 具體 fit 模式清單 | Page-fit（整頁）／Fit Width（項寬）／真實比例 1:1，三選一 |
| 8 | Fit 模式設定儲存層級 | 單書持久化，無全域預設（與濾鏡/裁切一致） |
| 9 | 新設定的資料庫落點 | 新增欄位到既有 `book_reader_prefs` 表（沿用現有全欄位 nullable 的單一表模式，不新建 `pdf_reader_prefs` 獨立表） |
| 10 | PDF 設定 UI 入口 | 新建獨立的 `PdfSettingsSheet`（不與 EPUB 用的 `ReaderSettingsSheet` 共用元件），`reader_screen.dart` 的齒輪按鈕依 format 分派到對應的 sheet |
| 11 | 濾鏡調整滑桿的預覽行為 | 即時預覽（拖動時即時重繪），鬆手後才寫入持久化——與 epic-3 字型大小/行高滑桿的既有慣例一致 |
| 12 | 手動裁切的 UI 互動方式 | 進入全螢幕裁切編輯模式（類似手機相簿的裁切工具，四角拖拉裁切框），非直接在閱讀畫面上疊加 overlay |
| 13 | NFR-1（100MB PDF < 2 秒）的驗收範圍 | 僅適用於基礎開啟（無濾鏡/無裁切）；啟用濾鏡或自動裁切後的效能另外寬鬆處理，允許翻頁後短暫延遲完成處理，不強制同一門檻 |

## 使用者流程（概要）

1. 使用者開啟一本 PDF，AppBar 出現齒輪「版面設定」按鈕（目前 PDF 沒有此按鈕，本 epic 新增）。
2. 點擊後開啟 `PdfSettingsSheet`：
   - **顯示分頁**：Fit 模式三選一（Page-fit／Fit Width／1:1）。
   - **濾鏡分頁**：對比度、亮度、加粗強度三支滑桿，拖動即時預覽。
   - **裁切分頁**：不裁切／智慧自動／手動選區三選一；選「手動選區」時導向全螢幕裁切編輯畫面，確認後回到閱讀畫面套用。
3. 所有調整即時反映在畫面上，鬆手/確認後寫入 `book_reader_prefs`，下次開啟同一本書沿用。

## 已知風險 / 待 Architecting 階段確認的技術細節

- **型態學膨脹的效能**：對點陣圖做像素級膨脹運算若實作不當可能明顯拖慢渲染，需在 Architecting/實作階段選定合理的演算法與強度範圍（例如限制在縮小後的取樣版本上運算，或使用 Android 內建的形態學/卷積 API），並依決策 #13 的寬鬆效能門檻驗證。
- **智慧自動裁切的邊界偵測演算法**：「近似白/近似黑」的判斷閾值、取樣頁數（第一頁 vs 前 N 頁平均）等屬於實作細節，留待撰寫 `plan-issue-N.md` 時具體訂定，不影響本次 Discovery 的決策方向。
- **裁切矩形的座標系統**：需為與頁面實際像素尺寸無關的相對座標（例如 0.0–1.0 的比例），避免不同 DPI/解析度渲染時跑位；具體型別定義見 `spec.md`。

## 範圍外 (Out of Scope)

- `epic-16-dual-page`（FR-41 橫向雙頁並排顯示）——已獨立分流。
- `epic-14-system-settings` 的全域預設層——本 epic 決議不需要。
- EPUB／TXT 的濾鏡或裁切——FR-11 僅描述 PDF；EPUB 固定版面（漫畫）的縮放已由 epic-3 Issue 10 處理，不在本 epic 範圍內重複討論。
- 型態學膨脹以外的進階影像處理（例如去斑、OCR 文字強化）——FR-11 明確列出的僅「對比度、亮度、加粗」三項。
