# Issue 20 報告：桌面寬度雙欄下 EPUB 目錄「目前章節」判定

日期：2026-11-11　結論：**缺陷已重現、根因已定位、已用選項 A（Dart 端覆寫）修復。** 見文末「修復」。

## 重現（Windows，1280x800，`sample_multi_chapter.epub`，拋棄式診斷測試）

目錄結構（DFS id）：0 第一章、1 第二章、2 第一節、3 第二節、4 第三章。第二章的兩節與第二章在同一個 spine。

| 操作 | relocate 回報（spine／tocItemId） | 目錄實際標示 | 預期（Q1 標準） |
|---|---|---|---|
| 開書 | 0／0 | 第一章 | 第一章 ✅ |
| 跳「第三章」 | **1／3** | **第二章第二節** | 第三章 ❌ |
| 跳「第二章」 | 1／3 | **第二章第二節** | 第二章 ❌（亦錯） |
| 跳「第一章」 | 0／0 | 第一章 | 第一章 ✅ |

**比 Issue 13 的描述更廣：** 不只「短章節被補前一節」，連「跳到第二章」也被標成它的最後一節。

## 根因

`view.js:#onRelocate` 以 relocate 的 `index` 與 `range` 呼叫 `TOCProgress.getProgress(index, range)`（`progress.js:42`）。該函式的規則是：**逐一檢查該 spine 內的目錄錨點，回傳「最後一個仍落在 range 內或之前」的目錄項**。

- 單欄時，range 只是一頁，規則等於「目前頁最靠後的標題」，剛好符合直覺。
- 雙欄時，range 涵蓋**左右兩欄**：
  1. 跳第三章：第三章不足一個雙欄，paginator 把前一節補進左欄，relocate 的 `index` 變成第二章（spine 1），range 起點在第二章 → tocItem 落在第二章最後一節。
  2. 跳第二章：整個第二章（含兩節）都在兩欄內，規則取「最後一個錨點」→ 第二節。

兩者的共同點：**雙欄把「目前」的定義從「這一頁」變成「這兩欄裡最後一個」。**

## 對 Q6 前提的更正（需要人類決定）

Q6 假設「一般翻頁目前是以左欄為準」。實際上**不是**：目前行為是「兩欄範圍內最後一個目錄項」，不是左欄。因此「一般翻頁維持現狀」與「以左欄為準」是兩件不同的事。見下方問題。

## 修復（人類選定選項 A，2026-11-11）

**做法：** 新增 `lib/reader/toc_jump_override.dart`（純 Dart）。使用者從目錄點選項目時記下該項的 `tocId`，目前章節優先採用它，直到使用者翻頁；`reader_screen.dart` 三處接線（建立、`_currentEpubTocPath` 取用、`onLocatorChanged` 餵位置）。不碰 `main.js`、不碰 vendor；一般翻頁行為不變。

**診斷中發現、影響設計的事實：** 雙欄跳轉會連續回報**兩次**：第一次落在目標（tocItem 正確，例如跳第三章回報 tocItem=4），約 **260ms** 後 paginator 補欄完成再回報一次（位置改成補入的前一節、tocItem=3，偏掉）。最初的版本把第二次回報當成翻頁而解除覆寫，測試仍失敗；因此規則改為落地後 **1500ms 排版穩定期**內的位置變化不解除覆寫，超過才視為使用者翻頁。1500ms 是約 6 倍餘裕的選擇，不是量測出的臨界值。

**測試：**
- `test/reader/toc_jump_override_test.dart`：7 項（含穩定期內／外、tocId 為 0、無 tocId、再次跳轉）。
- `integration_test/epub_toc_test.dart` 新增桌面寬度（1280x800）案例：依序跳第三章、第二章，斷言目前章節就是點選的那一章。修前在 Windows 失敗，修後 `epub_toc_test` 整份連跑 4 次全過（3/3 各次）。原本 400x800 手機版案例未動。
- `flutter analyze` 乾淨；全套 `flutter test` 5171 個通過；`check_integration_keys.js`、`check_l10n_hardcoded_strings.js` PASS。

## 已知限制與後續

- **穩定期是時間啟發式。** 極慢的機器上若補欄回報超過 1500ms 才到，覆寫會被誤解除、目錄又標錯。尚未在慢機器驗證。
- 跳轉目標剛好是目前位置、不產生任何 relocate 時，覆寫會多撐一次翻頁才解除（類別註解已記載）。
- **一般翻頁的雙欄判定沒有改**：目前是「兩欄範圍內最後一個目錄項」，不是左欄（見上方對 Q6 的更正）。翻頁到章節交界時目錄可能仍標成右欄的章節。這會改變 Android 橫向平板行為，建議另外登記為後續項目，不在本 Issue 處理。

- 只在這台 Windows 驗證；Android 橫向平板未驗證。
