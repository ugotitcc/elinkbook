## Issue 1：Fit 模式接上渲染（連續捲動路徑）

**Status:** done（PR #313）

**依賴：** 無。

**What to build：**
- 建立純 Dart 的「逐頁導覽規則」模組，先只放規則 1（縮放基準）與規則 2（頁內捲動範圍），輸入是單元內容尺寸、可視尺寸、Fit 模式。Issue 4、5、6 會擴充這個模組。
- `PdfReaderView` 讀取 `pdfFitMode`（Page-fit／Fit Width／真實比例）決定縮放基準，在**既有連續捲動**路徑下生效。連續捲動時基準以開書當下（或切換 Fit 模式、視窗尺寸改變當下）的目前頁尺寸換算，捲動途中不重算；最小縮放維持 pdfrx 原本的行為（與目前單元基準取較小者，只會更寬鬆），不強制「不可縮到基準以下」（使用者決定，見 epic.md 程式審查記錄 I-3）。Fit 模式啟用時，跳頁、翻頁、換 spread 都以目標單元的 Fit 基準縮放定位（不用 pdfrx 的 goToPage／goToArea，它們會把真實比例縮成頁寬、把 Fit Width 改成整個 spread 放進螢幕）。
- `PdfReaderView` 新增 `pdfFitMode` 參數，型別為可為空：`null` 表示不干預、沿用 `pdfrx` 現有的預設縮放行為（保護既有大量 widget 測試的基準，與 `pdfPageTurnMode` 的「widget 層預設保守、產品預設由 `ReaderScreen` 傳入」同一做法）；`ReaderScreen` 一律傳入解析後的 Fit 模式（目前設定面板只存檔、渲染端沒讀）。
- 初始縮放與（較寬鬆的）最小縮放透過 `pdfrx` 的 `sizeDelegateProvider`（提供初始縮放與最小縮放；它不能與已棄用的 `minScale`、`calculateInitialZoom` 等參數並用）交給 `pdfrx`，不要另外在 controller 上疊一層縮放，避免與 `InteractiveViewer` 衝突。
- 與雙頁模式、裁切模式相容：單元內容尺寸取 spread 矩形或裁切後矩形。

**測試要求：**
- 純 Dart 單元測試（接縫 1）：三種 Fit 模式在不同頁面／可視比例下的基準縮放、置中與起點規則、真實比例橫向溢出的起始側（依雙頁方向）、縱向最大捲動量（含未溢出為 0）。
- `PdfReaderView` widget 測試（接縫 2）：切換 Fit 模式後頁面縮放改變；預設（未傳或 Page-fit）下整頁完整放進螢幕。
- 既有 `pdf_reader_view_*` 測試全數不改而通過（零回歸）。

**驗收標準：** 真機開一份 PDF，在設定面板切換 Fit 模式，畫面確實隨之改變；雙頁與裁切下仍正確；`flutter analyze` 乾淨；上述測試通過。

**Blocked by：** 無。

## Issue 4：逐頁幾何隔離與瞬間換頁

**Status:** done（PR #317）

**依賴：** Issue 1、2、3。

**What to build：**
- 逐頁模式的 `layoutPages`：依 Issue 3 結論拉開單元間距（間距＝`max(超出量(前), 超出量(後)) + 50`，依視窗與單元尺寸即時計算），使可視矩形只與目前單元相交；`normalizeMatrix` 把平移鎖在目前單元範圍內（含置中與溢出規則）；雙頁 spread 與裁切版面用同一套隔離規則；快取外擴保留 pdfrx 預設 1.0（間距須落在 `(o, o + H × 外擴)`，見 `spec.md` 幾何隔離）。連續捲動的 `layoutPages` 不變。
- 規則 3、4 的 Page-fit 子集（下一頁／上一頁就是直接換到下一個／上一個單元，落在新單元頂端）與規則 6（絕對跳轉：落頂端、基準縮放，不繼承先前偏移與縮放）。**暫態降級：** 本 Issue 中即使單元有縱向溢出（Fit Width、長寬比極高的頁），相對步進仍一律當作 Page-fit 處理、直接整頁換頁；使用者仍可用拖曳在頁內捲動。頁內逐屏步進與「上一頁落在上一單元底端」留待 Issue 5 啟用。
- 逐頁模式下所有導覽（跳頁、翻頁、換 spread，包含 `goToPage`、`goToArea` 等）傳給 controller 的動畫時長一律為零，完全忽略 `pdfPageTurnAnimation`；否則畫面會高速滑過單元間被拉開的巨大空隙。
- 3×3 熱區、音量鍵、目錄、書籤、頁碼輸入、縮圖面板、全文搜尋面板、朗讀換頁接線到上述規則；換頁一律瞬間完成（不套用動畫時長）。
- 硬體鍵盤（PageUp／PageDown／Space／Home／End）：pdfrx 內建鍵盤處理在逐頁下會被 `normalizeMatrix` 夾回而失效，改以 `onKey` 接管為單元導覽（事後補記，來自 Issue 4 最終審查 I-2）。
- 當前頁回報為單元錨點頁，位置儲存規則不變。
- 視窗尺寸改變時維持同一單元。寬度改變（螢幕旋轉、分屏）：依新尺寸重算基準、偏移回頂端。僅高度改變（軟鍵盤彈出）：保留縮放與頁內相對位置，不跳回頂端（事後修訂，來自 Issue 4 最終審查 I-1）。
- 把產品預設切到逐頁：`ReaderScreen` 傳入解析後的偏好（預設逐頁）。

**測試要求：**
- 純 Dart 單元測試（接縫 1）：規則 6、單元沒有溢出時的步進（含第一／最後單元無動作）、spread 與裁切單元的幾何。
- `PdfReaderView` widget 測試（接縫 2）：逐頁下鄰頁不被繪製（對 Page-fit、Fit Width、雙頁、裁切各至少一例）、熱區與音量鍵瞬間換頁、跳轉落頂端、widget 層預設仍為連續捲動且連續捲動行為不變、頁碼回報為錨點頁。
- 既有 `pdf_reader_view_*` 測試不改預設而通過。

**驗收標準：** 真機開 PDF 預設為逐頁，整頁一次看完、鄰頁不可見、換頁瞬間；可在設定切回連續捲動且行為與以往相同；`flutter analyze` 乾淨；上述測試通過。

**Blocked by：** Issue 1、2、3。

## Issue 5：長頁步進、帶高亮跳轉與閱讀活動回報

**Status:** done（PR #318）

**依賴：** Issue 4。

**What to build：**
- 規則 3、4 完整版：單元縱向可捲動時，「下一頁」先頁內往下捲（步距＝可視高度減去 10% 重疊），到頁底後才換到下一單元頂端；「上一頁」對稱，頁內先往上退，到頂端後換到上一單元的**底端**，之後再按逐屏往上退。到頁底以 1 邏輯像素容許誤差判定。
- 規則 7：搜尋結果帶高亮矩形時，視窗自動帶到看得到高亮的位置（頂端已可見則維持頂端；否則垂直置中並夾範圍；高亮比可視高度高則上緣貼齊）。
- 規則 9：頁內垂直拖曳每累積 20 邏輯像素回報一次閱讀活動，換手勢或換單元歸零。接線合約：`ReadingSession` 由 `ReaderScreen` 私有持有，`PdfReaderView` 不得自行建構或引用它；`PdfReaderView` 新增 `onReadingActivity` 回呼（無參數），累積達門檻時呼叫；`ReaderScreen` 建構時把它接到 `ReadingSession` 既有的「回報一次閱讀活動」。
- 朗讀（TTS）沿用既有以頁為單位的安全視窗規則：長頁同一頁內不做句級追蹤捲動。

**測試要求：**
- 純 Dart 單元測試（接縫 1）：步進序列（頁高 2000、可視高 800、重疊 80：下一頁 0→720→1200→換頁；上一頁 1200→480→0→換到上一單元底端，再 1200→480→0）、上一單元不比螢幕高時落點為 0、剛好等高、到頁底 1 像素容許、第一／最後單元；規則 7 的三種情況；規則 9 的累積與歸零。
- `PdfReaderView` widget 測試（接縫 2）：Fit Width 長頁下熱區連續點擊的捲動與換頁序列；搜尋跳轉高亮落在視窗內；頁內拖曳觸發活動回報。
- `ReadingSession` 既有測試不改而通過。

**驗收標準：** 真機在 Fit Width 長頁上用熱區或音量鍵單手連續讀完一頁並換頁，往回按可逐屏退回；搜尋跳轉到長頁下半部時高亮可見；長頁上只用拖曳閱讀時閱讀時間持續計算；`flutter analyze` 乾淨；上述測試通過。

**Blocked by：** Issue 4。

## Issue 6：左右滑動翻頁與框選衝突處理

**Status:** done（PR #319）

**依賴：** Issue 4。

**What to build：**
- 規則 8：滑動判定（水平位移至少 56 邏輯像素、至少為垂直位移 2 倍、時長不超過 500 毫秒；頁面沒有橫向溢出；沒有長按拖曳框選進行中）。成立時依雙頁方向決定上一個或下一個單元（左到右：向左滑為下一個；右到左鏡像），落在新單元頂端、縮放回基準；不成立的手勢交由一般平移。
- 長按拖曳框選進行中暫時停用平移、縮放與滑動翻頁（沿用既有守衛）；2 指觸控取消框選的既有行為不變。
- 各門檻為模組內具名常數，標註為初始值、待真機校準。
- 手勢起訖時間戳記取自 `package:clock` 的 `clock.now()`，不用裸 `DateTime.now()`（比照 PDF 端 `TapZoneDetector` 的既有做法），讓 `flutter_test` 的 FakeAsync 能隨 `tester.pump()` 推進時間、時長門檻的臨界案例可重現。

**測試要求：**
- 純 Dart 單元測試（接縫 1）：門檻上下的臨界案例、斜向、太慢、有橫向溢出（真實比例放大後）、框選進行中、左到右與右到左的方向鏡像。
- `PdfReaderView` widget 測試（接縫 2）：未放大時水平滑動換頁；框選進行中滑動不換頁；放大有橫向溢出時滑動為平移。
- **待真機確認（不以自動測試守住）：** 滑動手感、各門檻是否合適、與長按框選及縮放平移的實際衝突；若需調整，另立小工單，不在本 Issue 內逕自改值。

**驗收標準：** 真機未放大時左右滑動換頁、方向正確；長按框選劃線時不會誤翻頁；放大後滑動是平移；`flutter analyze` 乾淨；上述自動測試通過，待真機確認項目已記錄於 `epic.md`。

**Blocked by：** Issue 4。
