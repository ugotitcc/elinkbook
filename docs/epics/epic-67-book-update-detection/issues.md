## Issue 1：核心——偵測與取代

Status: completed（已合併 PR #386；[plan-issue-1.md](plans/plan-issue-1.md)）

**範圍**：擴充 `BookImportService`（既有抽象介面）的兩個能力，三個入口之後共用。本 Issue 不含任何畫面。

- **偵測**：輸入新檔位置與顯示名稱；輸出分類——新書／重複／更新版（高信心或疑似，附候選書清單，識別碼命中者排最前，並帶舊檔是否可讀）／無法處理。
  - 格式一致為先決條件（TXT 與 MD 視為不同格式）。
  - 第一層：EPUB 的 OPF identifier 相同；第二層：書名＋作者正規化後完全相同，作者為空不進入。
  - 重複 vs 更新版：身份相同後比整檔 SHA-256；舊檔讀不到時降級為更新版並標示「舊檔無法存取」。
  - 整檔雜湊以串流於背景計算，不阻塞介面。
- **取代**：輸入目標書與新檔；輸出成功（附更新後的書）或失敗（格式不符、新檔解析失敗、寫入失敗）。
  - `Book.id` 與內容指紋不變；進度、書籤、劃線、備註、分類、單書版面偏好保留。
  - 書名、作者、封面、全書字元數、固定版面判定以新檔重建；TXT／MD／CBZ 重新合成；新版無封面時清除舊封面。
  - 全文索引：復用既有的單書索引清除（`FullTextSearchSettingsRepository.clearBookIndex`），再以 `handleBookAvailable` 重新排程（未啟用則只清除）。
  - 原子性：新檔先寫暫存名稱，成功後才取代式搬移覆蓋正式檔名；任何階段失敗清掉暫存、舊書完全不動。
  - 取代能力的選填來源參數：雲端檔案識別碼、遠端站點識別碼、遠端書籍識別碼、遠端下載網址。供 Issue 4 取代時補寫來源欄位，避免之後回頭改介面。
- **更新候選**資料型別與「丟棄候選」能力（清理預先處理的暫存檔）。
- **「並存」能力**：服務提供「強制作為新書匯入」（以候選為輸入），略過更新版判定、指派新書籍識別碼、計算新指紋、建立新書，完成後清理暫存檔。否則 Issue 2 選「並存」再走一般匯入會再次被判為更新版，造成對話框迴圈。
- **匯入管線整合（邊界歸屬 Issue 1）**：`importFiles` 與 `importFolder` 內部整合偵測能力。遇到更新版時不直接當新書寫入，而是預先處理並放入匯入結果的更新候選清單回傳；其餘檔案（新書、重複）行為與現況一致。Issue 2 只負責畫面。
- 失敗原因採密封型別或列舉，不使用字串旗標。

**單元測試要求**（假的 `LibraryRepository` 加假的原生 channel；沿用既有匯入服務測試做法）：

- 分類：新書、重複、高信心更新版、疑似更新版、無法處理。
- 格式不同與 TXT／MD 互換不進入候選；作者為空不進疑似層；書名作者正規化（空白、大小寫、全半形）；多候選排序。
- 舊檔讀不到降級為更新版並帶旗標。
- 取代：`Book.id`／指紋不變；註記、進度、分類、版面偏好保留；中繼資料更新；無封面時舊封面清除；字元數與固定版面重置；索引清除並在啟用時重排程；TXT／MD／CBZ 重新合成。
- 原子性：在複製、合成、解析、寫入各階段注入失敗，舊書、舊檔、舊衍生資料不動且無殘留暫存；合成格式新檔成功前不覆蓋正式檔名。
- 丟棄候選後暫存檔消失；取代或並存完成後暫存檔消失。
- 「強制作為新書匯入」：建立新書、新識別碼與新指紋，不再被判為更新版，且不影響原書。
- 取代帶來源參數時，雲端或遠端欄位被正確寫入。
- `importFiles`／`importFolder`：更新版進入結果的更新候選清單而不被寫入；新書與重複的既有行為不回歸（含同批次重複來源位置的跳過計數）。

## Issue 2：本機匯入入口與彙整清單

Status: completed（已合併 PR #387；[plan-issue-2.md](plans/plan-issue-2.md)）。真機手動驗證由人類另行執行，結果補記於 epic.md

**範圍**：書架畫面接收匯入結果中的更新候選清單（由 Issue 1 在服務端產生），彈出一份彙整清單並驅動後續操作（單檔也用同一份）。本 Issue 只做畫面與接線，不改服務端匯入管線。

- 每本一個選項：取代（預設，呼叫取代能力）／並存（呼叫「強制作為新書匯入」）／跳過；多候選者可挑候選書或「當成新書」；清單提供「全部取代」「全部跳過」。
- 取代前的確認文字提示「既有註記位置可能因內容改版而偏移」。
- 跳過、關閉清單、返回或取消時呼叫「丟棄候選」；取代或並存完成後自動收尾。
- 「N 本已存在，已跳過」提示維持，並與更新版清單分開呈現。
- 取代成功後須 evict 該書封面的 `FileImage` 快取（`PaintingBinding.instance.imageCache.evict(FileImage(File(coverPath)))`，見 ADR 0040 與 F8）。
- 新增字串四語系同步。
- 實測發現：章節索引超界會讓開書卡死、跳轉位置不動；元素路徑不存在不算失敗，詳見 `plans/plan-issue-5.md`。

**單元測試要求**（widget test）：

- 清單顯示每本的選項與信心等級；多候選時可選候選或當成新書。
- 「全部取代」「全部跳過」動作正確；跳過與離開後暫存檔被丟棄。
- 取代確認文字含偏移提示。
- 純重複只顯示既有跳過提示，不出現更新版清單。

## Issue 3：手動入口與強制重新連結

Status: ready-for-agent（依賴 Issue 1）

**範圍**：

- 書籍動作選單新增「用新檔案更新此書」（`BookAction` 列舉新增 `updateBook`，選項 Key 為 `book_action_update_book`，比照既有 `book_action_*` 命名）：選檔後只檢查格式相同，不做身份比對；通過即進入取代確認（含偏移提示）。格式不符回傳明確原因並拒絕。
- `relinkBook` 內容不符、格式相同時，回傳可由呼叫端繼續確認的結果；畫面詢問「強制重新連結」，確認後只更新檔案路徑（不改指紋）。格式不符仍拒絕。此規則對所有書通用，不另記錄哪本書被取代過。
- 取代成功後須 evict 該書封面的 `FileImage` 快取（`PaintingBinding.instance.imageCache.evict(FileImage(File(coverPath)))`，見 ADR 0040 與 F8）。
- 新增字串四語系同步。

**單元測試要求**：

- 手動更新：格式相同成功；格式不同拒絕；略過書名作者與 identifier 比對。
- `relinkBook`：內容不符＋格式相同 → 回傳「待確認」結果；確認後路徑更新、指紋不變；格式不符仍拒絕；既有成功與其他失敗分支（已在書庫、失敗）不回歸。
- 畫面：選單項目存在於適用格式；強制重新連結確認對話框的取消與確認。

## Issue 4：下載佇列「待確認更新」

Status: ready-for-agent（依賴 Issue 1）

**範圍**：雲端（Google Drive／OneDrive）與 Calibre 下載。

- 選檔階段維持既有「已在書庫，仍要下載？」提示不變（作為迴歸）。
- 偵測與結算一律經由 `QueuedDownloadJob` 抽象介面，`DownloadQueueController` 不直接依賴匯入服務，維持「來源無關」的既有分層。介面新增兩個能力：對暫存檔偵測更新版（回傳更新候選或無）、依使用者選擇結算（取代／並存／跳過）。`CloudDownloadJob`、`RemoteDownloadJob` 各自持有匯入服務與來源參數，由它們把雲端檔案識別碼、遠端站點與書籍識別碼帶入取代能力。
- 下載完成後呼叫偵測：更新版 → 項目進入新狀態「待確認更新」，佇列立即處理下一筆，不彈對話框、不阻塞。整檔雜湊相同的重複沿用既有行為。
- 項目攜帶偵測結果、新檔暫存位置、來源識別資訊（雲端檔案識別碼或遠端站點與書籍識別碼），讓取代／並存補寫來源欄位。
- 偵測為更新版後，新檔立即從系統暫存位置移到 App 私有專屬暫存目錄（位於應用程式內部儲存空間下的獨立子目錄，用平台路徑提供者取得，不需額外儲存權限）。
- 下載面板點開項目 → 取代／並存／跳過；佇列提供對應操作並負責刪除暫存檔。
- 待確認清單不跨重啟持久化；App 啟動時清掃專屬暫存目錄殘留。
- 新增字串四語系同步。

**單元測試要求**（沿用既有下載佇列測試）：

- 更新版 → 項目進入「待確認更新」且佇列繼續處理其他項目。
- 暫存檔移入專屬目錄；跳過、取代完成、並存完成、從面板移除後暫存檔消失。
- 取代／並存正確補寫雲端或遠端來源欄位。
- 啟動清掃會刪除專屬目錄殘留。
- 選檔階段重複提示行為不變（widget test 迴歸）。

## Issue 5：Foliate 格式降級

Status: completed（已合併 PR #383；[plan-issue-5.md](plans/plan-issue-5.md)）。真機整合測試 `foliate_navigation_degrade_test.dart` 由人類於真機補跑。

**範圍**：EPUB／KF8／CBZ／TXT／MD。

- 開書流程把儲存的進度比例一併傳給閱讀器；精確定位（CFI）失敗時不得讓整本書載入失敗，改用進度比例定位，並向 Dart 端回報「閱讀位置已降級」。
- 註記與書籤跳轉請求同時帶精確定位與概略進度；精確定位失敗自動改用概略進度，並回報「註記位置已降級」。
- Dart 端據此顯示「位置已變更，已跳至概略進度」提示。
- 橋接契約：JS→Dart 通訊名稱一律登錄在 `FoliateBridgeHandlers`（新增 `onNavigationDegraded`，不得硬編碼）；降級原因以 Dart 列舉表達（閱讀位置、註記）；`ReaderJumpTarget` 沿用既有 `progression` 欄位作為降級進度（與 `cfi` 並存時的語意，不新增欄位）；`FoliateReaderView` 新增降級回呼，由 `ReaderScreen` 接線顯示提示。
- 降級是通用安全網，同時涵蓋「新檔加舊位置」與「舊檔加新位置」（跨裝置同步）。
- 動到 `foliate/main.js`：改動後依專案慣例跑 `node app/tool/check_foliate_es_compat.js`。
- 新增字串四語系同步。

**單元測試要求**：

- Dart 端：收到降級回報時顯示提示；進度比例正確傳入閱讀器；跳轉請求帶概略進度。
- 若有 Node：以 harness 情境驗證——無效 CFI 開書不拋錯並以進度定位；無效 CFI 跳轉自動降級並回報；有效 CFI 不觸發降級。
- **真機整合測試**（`integration_test/`，必須接真實裝置，專案慣例）：以修訂版內容載入舊位置，確認開書成功、跳轉降級、提示出現。

## Issue 6：PDF 降級

Status: ready-for-agent（建議 Issue 5 之後，共用提示）

**範圍**：PDF 註記與閱讀位置的頁碼超出總頁數時，限制在最後一頁，並讓呼叫端得知發生降級，由閱讀畫面統一顯示與 Issue 5 相同的提示。兩個防護點：

- **開書階段**：文件載入完成後，若初始頁碼超出總頁數，導回最後一頁並通知降級（現況直接把超界頁碼交給 `pdfrx`）。
- **跳頁階段**：跳頁遇到超界時（現況為直接 `return` 靜默忽略），限制至最後一頁、執行跳頁並通知降級。
- `PdfReaderView` 新增降級回呼，由 `ReaderScreen` 接線；降級原因的列舉與提示文字沿用 Issue 5 的定義。

**單元測試要求**：

- 頁碼超界 → 限制在最後一頁並通知降級；頁碼有效 → 不降級、不通知。
- 開書時初始頁碼超界 → 開在最後一頁並通知降級；初始頁碼有效 → 不降級。
- 閱讀畫面收到降級通知時顯示提示。
- 既有跳頁、三態雙頁、書籤跳轉不回歸。
