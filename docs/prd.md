# 產品需求文件 (PRD)：全能跨平台電子書閱讀器

## 1. 執行摘要 (Executive Summary)

本產品為全能跨平台電子書閱讀解決方案，旨在解決繁體中文數位閱讀在不同平台上的排版一致性問題。核心競爭力在於 **直排中文（Vertical Writing）** 的完美支援與深度排版客製化，並透過雲端同步提供無縫的跨裝置閱讀體驗。

---

## 2. 成功準則 (Success Criteria)

1. **渲染準確性**：ePub3、PDF 及 TXT 核心格式於代表性測試書籍集（涵蓋常見版式與編碼）中達成零排版缺陷。
2. **直排體驗**：直排繁體中文之標點符號（如：破折號、引號）與避頭尾處理符合標準排版規範。
3. **高效效能**：100MB 以上之 PDF 開啟速度小於 2 秒。
4. **無感同步**：跨裝置閱讀進度同步延遲低於 2 秒，衝突解決成功率達 99.9%。
5. **知識留存**：支援將劃線、備註與書籤清單導出為標準 Markdown 格式，可匯入主流筆記軟體，提升閱讀後的二次知識產出效率。
6. **格式擴充可用性**：KF8 (AZW3)、Markdown (MD) 之排版品質達到與 ePub3 同等水準（因共用同一渲染管線）；CBZ 之驗收門檻為「圖片正確顯示且翻頁方向正確」——與準則 #1 的「零排版缺陷」門檻區隔，因 CBZ 為圖像格式，無排版可言（見 FR-43）。
7. **語音朗讀可用性**：Phase 1 MVP（系統原生語音＋句級同步高亮）於所有 Foliate 格式（ePub3／KF8／TXT／MD）正確朗讀且高亮不偏移；PDF 語音朗讀之多欄/表格排版朗讀順序為明確記錄之已知限制，不列入零缺陷門檻（見 FR-45～47）。
8. **遠端書庫可用性**：OPDS／Calibre 站點新增、目錄瀏覽、下載、匯入、移除本機快取、重新下載、刪除站點之端到端流程無阻塞性問題（見 FR-44；已由 `epic-30-calibre-remote-library` 真機驗證達成，詳見該 Epic `reviews/review-issue-5.md`）。

---

## 3. 產品範圍 (Product Scope)

### 3.1 包含範圍 (In-Scope)

- **MVP 階段**：支援主流格式 (ePub3, PDF, TXT) 匯入、橫排與直排切換、本機與雲端同步、劃線註記、書籤管理、基礎圖書管理。
- **後續擴展**：全文檢索、社群分享、閱讀統計熱點、Markdown 註記導出、E-Ink 設備優化、格式擴充（KF8 (AZW3)、CBZ、Markdown (MD)，見 FR-43；MOBI／FB2 經評估後排除於本次範圍，列為未來獨立評估項目）、遠端書庫整合（OPDS／Calibre，見 FR-44）、語音朗讀（TTS，見 FR-45～47）、簡繁轉換（見 FR-48）、多語系介面（見 FR-49）。

### 3.2 不包含範圍 (Out-of-Scope)

- **數位版權管理 (DRM)**：本產品不支援解除 Adobe DRM 或其他加固之版權保護機制。
- **電子書商店**：不提供圖書採購、租閱等商業交易平台功能。
- **多媒體編輯**：不支援對 PDF 內容進行深度編輯（如修改文字或圖片）。
- **社交網絡系統**：本產品不包含完整的社交平台（如動態牆、好友系統），僅支援單向的內容分享。

### 4.6 UX/UI 設計需求

1.  **介面原則**：採高度極簡主義規劃，避免過多常駐選單干擾閱讀。
2.  **單手全域操作**：翻頁、目錄開啟與基礎調節應可透過單手熱區 (Hot zones) 完成。
3.  **E-Ink 友善設計**：核心導航 UI 提供高對比模式，減少動態過渡效果以避免殘影。
4.  **一致性語言**：Mobile 與 Desktop 應保持相似的按鈕與選單佈局邏輯，降低跨設備學習成本。

## 5. 非功能性需求 (Non-Functional Requirements)

1. **啟動效能**：冷啟動時間低於 1.5 秒；100MB 以上文件載入（含渲染）不超過 2 秒（**主要適用於 PDF，ePub/TXT 檔案通常遠小於此門檻**）。
2. **檢視回應**：全書庫搜尋回應時間在 1,000 本書規模下應小於 500ms。
3. **離線強韌性**：支援離線閱讀與快取，連網後 2 秒內自動完成數據交換與衝突解決。
4. **渲染流暢度**：頁面翻轉保持 60 FPS，字型載入不得造成 UI 阻塞。
5. **定位精確度**：確保跨裝置同步位置精確一致：**EPUB 使用 CFI 精確至字符級；PDF 精確至頁碼；TXT 精確至字元偏移量**（此為書籤/進度同步之基準精度；**劃線與備註之定位精度高於此基準，另見 FR-15**）。
6. **平台相容性**：Android 版本須至少支援 **Android 11 (API 30)** 以上裝置正常執行，不得將最低支援版本限制在比這更新的門檻。

## 6. 技術決策備註 (Implementation Notes)

- **目錄與分頁**：針對流式 ePub，建議採背景預渲染機制計算節點位置，以呈現穩定的頁碼參考；TXT 則採用固定字符數量換算偽頁碼。
- **高效檢索**：考量書庫規模，建議採用 SQLite FTS5 或類似的全文檢索索引機制以確保檢索效能。
- **同步技術**：已決策採用 PocketBase 處理高頻位置更新（曾評估 Firebase、Supabase 作為替代方案）。
- **統計模組**：參考 Readest 模式，使用本地資料庫儲存每日閱讀片段，並進行彙整顯示。
- **格式擴充（FR-43）之渲染/解析架構決策**（TXT 改採與 MD 共用之渲染管線、匯入時落地轉換、純 Dart-only 格式解析等）不在 PRD 範圍，詳見 `docs/adr/0023-multi-format-foliate-pipeline-txt-route-reversal.md`。
- **遠端書庫（FR-44）之技術架構**：已完成（`epic-30-calibre-remote-library`，Issue 0-6，PR #157-163），完整技術決策（`OpdsClient`／`RemoteServerRepository` 介面契約、`remote_servers`／`books` schema 擴充、序列下載佇列、雙層重複匯入偵測、`RemoteThumbnailCache` 雙層快取等）不在 PRD 範圍，詳見該 Epic 自身的 `design.md`／`spec.md`（歸檔前位置見 `docs/epics.md` 該列）。
- **語音朗讀（FR-45～47）之技術架構**：不在 PRD 範圍，完整研究與建議架構詳見 `docs/research/tts_integration_architecture_research.md`（Foliate 格式篇：Provider 抽象層、音訊快取、CFI↔TTS Timeline 對齊、重用既有 `overlayer.js`／`epubcfi.js` 而非另建高亮機制）與 `docs/research/pdf_tts_integration_architecture_research.md`（PDF 篇：頁碼＋文字座標定位、`pdfrx.loadStructuredText()` 既有能力、與劃線/書籤持久化模型分離之風險提醒）。兩份報告建議分期實作（系統原生 TTS＋句級高亮 → 分塊快取＋雲端 API → 端側神經語音），PDF 排在 Foliate 格式之後獨立成期。
- **簡繁轉換（FR-48）之技術架構**：尚無研究報告，技術路線（例如是否採用 OpenCC 或等效字元/詞彙對照表方案、於 WebView 內對 DOM 文字節點做顯示層轉換而不修改底層檔案、與既有 CFI 定位／劃線座標之相容性）留待該功能啟動 Discovery／Architecting 階段（`/grill-with-docs`／`/to-spec`）決定，不在 PRD 範圍。
